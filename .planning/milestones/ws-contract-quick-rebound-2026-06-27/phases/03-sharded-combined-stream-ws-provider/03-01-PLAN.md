  <action>
    在 `lib/services/rebound/rebound_kline_stream_service.dart` 创建 `ReboundKlineStreamService` 类（per D-01）。

    **核心设计：**

    1. **Sharding（per D-02）**：
       - 常量：`_maxStreamsPerConnection = 1024`，`_baseWsUrl = 'wss://fstream.binance.com/stream'`
       - `connect(List<String> symbols, List<String> timeframes)` 方法：按标的分片，每分片 ≤1024 stream
       - 分片逻辑：`chunks = symbols.chunks((symbols.length * timeframes.length / 2).ceil())`
       - 每个分片一个 `WebSocketChannel`，连接后用 SUBSCRIBE JSON 消息订阅 stream（per D-02 支持动态 TF 切换）
       - Stream 名称格式：`{symbolLower}@kline_{interval}`（mark price kline，per D-08）

    2. **消息解析 + k.x 过滤（per D-03）**：
       - combined-stream 消息格式：`{"stream":"btcusdt@kline_15m","data":{...kline...}}`
       - 解析 `data['k']` 字段，提取：
         - `k['x']` (bool) — 是否已收盘，**硬断言：if (!k['x']) 仅更新 buffer 尾部，不触发事件**
         - `k['t']` (int) — openTime (ms)
         - `k['o']`, `k['h']`, `k['l']`, `k['c']`, `k['v']` (String) — OHLCV
       - 构造 `KlineData` 时使用 mark price（stream 名含 @kline_ 即 mark price 版本，per D-08）

    3. **Rolling buffer 管理**：
       - `_buffers: Map<String, Map<String, List<KlineData>>>` — symbol → timeframe → window
       - 收到 partial kline：更新 buffer 尾部（如果 openTime 相同则 replace，新的则 append）
       - 收到 closed kline：更新 buffer 尾部 + 通过 `StreamController<ClosedKline>` 广播事件
       - `ClosedKline` 数据类：`{symbol, timeframe, window: List<KlineData>}`
       - `windowOf(String symbol, String tf)` 方法：返回当前 buffer 的不可变副本

    4. **暴露 Stream**：
       - `Stream<ClosedKline> get closedKlineStream` — 编排器订阅此流
       - 每个连接独立 `_onMessage` 回调，解析后统一路由到 buffer 更新 + 事件广播

    5. **连接状态**：
       - `ReboundConnectionState` 枚举：`disconnected, connecting, connected, reconnecting, warmingUp`
       - `Map<int, ReboundConnectionState>` 每分片独立状态
       - 全局状态为所有分片中最差的状态

    **不要实现重连/warm-up/回填逻辑**——Task 2 负责。

  <action>
    在 ReboundKlineStreamService 中添加重连、warm-up、回填、熔断逻辑。

    **1. 重连（per D-07）**：
    - 每个分片独立重连定时器
    - 指数退避 + jitter：`delay = min(baseDelay * 2^attempts + random(0, jitterMs), maxDelay)`
      - baseDelay = 5s, maxDelay = 60s, jitterMs = 2000
    - 重连后执行 REST 回填（见下）
    - 最大重连次数 50（长期运行），超过标记该分片为 `disconnected` 并记录日志

    **2. REST 回填（per D-07）**：
    - 每个 (symbol, tf) 维护 `lastConfirmedCloseTime: Map<String, Map<String, DateTime>>`
    - 断连期间记录断连开始时间 `_disconnectStartTime`
    - 重连成功后：对每个 (symbol, tf) 用 `BinanceApiService.getKlines(symbol, interval, startTime: lastConfirmedCloseTime, endTime: now)` 拉取缺口
    - **整体重算**：将 REST 返回的 K 线追加到 buffer，然后重算所有指标（非增量插入——避免 ATR/RSI 序列不连续，per D-07）
    - REST 回填期间暂停广播 ClosedKline 事件（避免用不完整数据触发检测）
    - 回填完成后恢复正常广播

    **3. Warm-up（per D-06）**：
    - 新标的加入订阅时（`addSymbols()` 或首次 `connect()`），先 REST 拉 100 根历史 K 线（使用 `BinanceApiService.getKlines()`，per D-06）
    - 期间该 (symbol, tf) 标记为 `warming-up`（不广播 ClosedKline 事件）
    - REST 拉完后标记为 `ready`，开始正常 K 线流处理
    - `isWarmingUp(String symbol, String tf)` 方法供编排器查询

    **4. 解析失败熔断（per D-07）**：
    - `_parseErrorCount: Map<int, int>` 每分片独立计数
    - 解析失败（json.decode 抛异常、缺少 k 字段、类型转换失败）时计数 +1
    - 连续 N 次（N=10）失败触发熔断：关闭该分片连接，标记为 `disconnected`，记录日志
    - 成功解析时重置计数为 0

    **5. 写入 drift klines 表（per D-10）**：
    - 收到 closed kline 时，使用 `DatabaseHelper` 写入 klines 表
    - `INSERT OR REPLACE` 幂等写入（symbol, interval, openTime 为 PK）
    - 异步写入，不阻塞事件广播

    **测试要求：**
    - mock WebSocket channel 和 BinanceApiService
    - 测试 warm-up 期间不广播 ClosedKline
    - 测试重连后 REST 回填被调用
    - 测试连续解析失败触发熔断
    - 测试 lastConfirmedCloseTime 在收到 closed kline 后更新
