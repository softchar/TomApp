创建 `DataImportService` 类 (`lib/services/rebound/data_import_service.dart`)，提供历史 K 线数据下载、解压、解析、批量写入的完整管线：

1. **常量定义**：`static const _baseUrl = 'https://data.binance.vision/data/futures/um/monthly/klines'`。最大下载并发数 `_maxConcurrency = 5`。ZIP 响应体大小上限 `_maxZipBytes = 200 * 1024 * 1024`（200MB 防 ZIP bomb）。CSV 列索引：0=openTime, 1=open, 2=high, 3=low, 4=close, 5=volume, 6=closeTime(ignore), 7=quoteVolume(ignore), 8=trades(ignore), 9=takerBuyBaseVol(ignore), 10=takerBuyQuoteVol(ignore), 11=ignore。

2. **`Future<List<KlineData>> downloadMonth({required String symbol, required String interval, required int year, required int month})`**：构造 URL `${_baseUrl}/${symbol}/${interval}/${symbol}-${interval}-${year}-${month.toString().padLeft(2, '0')}.zip`。通过 `http.get` 下载，校验 statusCode==200，否则抛出异常。使用 `ZipDecoder().decodeBytes(response.bodyBytes)` 解压。ZIP 内每月仅含 1 个 CSV 文件，取 `archive.first`。调用 `_parseCsv` 解析。

3. **`List<KlineData> _parseCsv(String csv, {required String symbol, required String interval})`**：按换行 split，过滤空行。每行按逗号 split 为 12 列。时间戳标准化：`final rawTime = int.parse(cols[0])`，若 `rawTime > 10000000000000`（13 位以上）则 `timeMs = rawTime ~/ 1000`，否则 `timeMs = rawTime`。用 `DateTime.fromMillisecondsSinceEpoch(timeMs)` 创建 `KlineData(time:..., open:..., high:..., low:..., close:..., volume:...)`。注意：**KlineData 不携带 symbol/interval 字段**——调用方通过外层参数维护，数据导入管线在写入 drift 时注入。

4. **`Future<int> importHistoricalData({required AppDatabase db, required BacktestConfig config})`**：遍历 config.symbols × ['15m'] 周期 (= Phase 第 1 步只用 15m，后续 Phase 可扩展为 monitoredTimeframes 常量引用的多周期)。按月计算需要下载的月份列表（从 config.startDate 到 config.endDate）。对于每个 `(symbol, interval, year, month)` 三元组，并发下载（上限 5 并发，用 `Future.wait` 分批控制）。下载后通过 drift `batch` API 按每批 1000 条写入：`db.klines.insertAll(lines, mode: InsertMode.insertOrIgnore)`。**去重**：同一 `(symbol, interval, openTime)` 已存在则跳过（drift 复合主键自动处理，insertOrIgnore 即可）。返回成功写入的 K 线总条数。

5. **`Future<void> gapFill({required String symbol, required String interval, DateTime? startTime, DateTime? endTime, required AppDatabase db})`**：当月缺口通过 REST `/fapi/v1/klines` 补足。构造 URL `https://fapi.binance.com/fapi/v1/klines?symbol=${symbol}&interval=${interval}&limit=1000&startTime=${startMs}&endTime=${endMs}`。响应 JSON 通过 `KlineData.fromBinanceResponse` 解析（复用已有 factory）。写入 drift（同 insertOrIgnore）。遵守 Binance REST 权重限制（每条请求 weight=1，连续请求间隔 200ms）。如果数据量超过 1000 条需分页，用最后一条的 openTime+1 作为下一页的 startTime。

6. **`Future<List<String>> fetchTopSymbols({int count = 100})`**：从 Binance `/fapi/v1/ticker/24hr` 获取 24h 交易量排序的前 count 个 USDT 永续 symbol。按 quoteVolume 降序排列，取前 count 个。返回 `List<String>`。请求失败时抛出异常（不含降级默认列表——数据源不可靠时不应静默回退）。

7. **下载路径**：使用 `dart:io` 的 `Directory.systemTemp.createTemp('backtest_import_')` 作为临时解压目录，导入完成后删除临时文件。

创建 `FundingRateService` 类 (`lib/services/rebound/funding_rate_service.dart`)：

1. **常量**：`static const _baseUrl = 'https://fapi.binance.com/fapi/v1/fundingRate'`。分页大小 `_pageLimit = 1000`。请求间隔 `_requestDelay = Duration(milliseconds: 700)`（遵守 500 req/5min 共享权重限制，留余量）。

2. **本地缓存**：`final Map<String, List<FundingRate>> _cache = {}`。key 为 symbol。

3. **`Future<List<FundingRate>> fetchHistory({required String symbol, DateTime? startTime, DateTime? endTime})`**：对齐 RESEARCH.md 4.2 节分页模式。startTime 和 endTime 以毫秒时间戳传入。循环分页：每次请求构造 URI `${_baseUrl}?symbol=${symbol}&limit=${_pageLimit}&startTime=${startMs}&endTime=${endMs}`。响应 JSON 数组每项取 `fundingRate`（String 转 double）、`fundingTime`（int 毫秒）、`symbol`（String）。累积到 `allRates`。下页 startTime = 本页最后一条 `fundingTime + 1`（无重复）。数据为空时终止循环。**请求间隔**：每次请求后 `await Future.delayed(_requestDelay)`。拉取完成后更新 `_cache[symbol] = allRates`。

4. **`Future<double?> getRate(String symbol, DateTime timestamp)`**：给定 symbol 和时间戳，从缓存中查找该时刻生效的 funding rate。funding rate 在结算时刻（00:00/08:00/16:00 UTC）后 8 小时内有效。查找逻辑：找 `fundingTime <= timestamp` 且 `fundingTime > timestamp - 8h` 的最新一条。若缓存未命中，自动触发 `fetchHistory` 填充。

5. **`Future<void> prefetch(List<String> symbols, DateTime startTime, DateTime endTime)`**：批量预拉取，用于回测引擎启动前一次性加载所有标的的 funding rate 数据。遍历 symbols 列表，每个 symbol 独立拉取（串行或有限并发，共用 `_requestDelay` 限流）。

6. **扩展 Task 2 的测试文件**：在 `test/services/rebound/data_import_test.dart` 末尾追加 `FundingRateService` 的测试用例（约 3 个 test case）：分页拉取完整数据验证最终列表长度等于预期总条数、getRate 查找某时刻正确的 funding rate、缓存命中避免重复 HTTP 请求。共享 `test/services/rebound/test_fixtures.dart` 中的 `mockFundingRates`。
