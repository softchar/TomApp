类名 ReboundNotificationService。持有 FlutterLocalNotificationsPlugin _plugin 实例。

静态常量：
- _highChannelId = 'rebound_high'
- _medChannelId = 'rebound_med'
- _highChannelName = '反弹强信号'
- _highChannelDesc = '高分反弹监控候选——响铃+震动提醒'
- _medChannelName = '反弹提示'
- _medChannelDesc = '中等反弹监控候选——横幅提醒'

方法 Future\&lt;void\&gt; initialize()：

1. 通过 AndroidFlutterLocalNotificationsPlugin? android = _plugin.resolvePlatformSpecificImplementation\&lt;AndroidFlutterLocalNotificationsPlugin\&gt;()
2. 若 android == null → 直接 return（非 Android 平台）
3. 创建 rebound_high 渠道：AndroidNotificationChannel(_highChannelId, _highChannelName, description: _highChannelDesc, importance: Importance.max, playSound: true, enableVibration: true, vibrationPattern: Int64List.fromList([0, 500, 200, 500]))
4. 创建 rebound_med 渠道：AndroidNotificationChannel(_medChannelId, _medChannelName, description: _medChannelDesc, importance: Importance.defaultImportance, playSound: true, enableVibration: false)
5. 创建两个渠道使用 await android.createNotificationChannel()（渠道创建幂等，重复调用不崩溃不重建）

也调用 _plugin.initialize() 设置 onDidReceiveNotificationResponse 回调：收到点击事件后，若 payload 非空 → 通过 AppNavigation.navigateToKline(payload!) 跳转到 KlineScreen。

方法 Future\&lt;void\&gt; dispatch(AlertDecision decision)：

switch (decision.level) 分派：
- AlertLevel.high → channelId = _highChannelId, importance = Importance.max, priority = Priority.high, vibrate = true
- AlertLevel.medium → channelId = _medChannelId, importance = Importance.defaultImportance, priority = Priority.defaultPriority, vibrate = false
- AlertLevel.low → return（不发通知，仅看板可见）

构建通知标题 _buildTitle(decision)：格式 "{SYMBOL} {TIMEFRAME} 反弹监控候选"（例如 "BTCUSDT 15m 反弹监控候选"）。若 decision.coalescedTimeframes.length > 1，格式改为 "{SYMBOL} 多周期共振 反弹监控候选"。

构建通知正文 _buildBody(decision)：格式 "评分 {score} | 跌幅 {dropMagnitude}×ATR | 回补 {recoveryPercent}%"（例如 "评分 82 | 跌幅 2.5×ATR | 回补 65%"）。取 decision.signal 的 score/dropMagnitude/recoveryRatio 字段。recoveryPercent = (recoveryRatio * 100).toStringAsFixed(0)。

调用 _plugin.show(decision.symbol.hashCode, title, body, NotificationDetails(android: AndroidNotificationDetails(channelId, channelName, importance: importance, priority: priority, enableVibration: vibrate, icon: '@mipmap/ic_launcher')), payload: decision.symbol)。

注意：与现有 NotificationService（funding_rate_channel + pump_alerts）完全独立——不修改 notification_service.dart。两个 NotificationService 各自持有 FlutterLocalNotificationsPlugin 实例，互不干扰。渠道 ID 命名空间隔离（rebound_high/rebound_med vs funding_rate_channel）。

导入项：flutter_local_notifications、lib/models/alert_level.dart、lib/utils/app_navigation.dart、lib/models/rebound_signal.dart。

创建 lib/providers/alert_settings_provider.dart。extends ChangeNotifier。

私有字段（从 SharedPreferences 读取，若不存在用默认值）：
- Map\&lt;String, bool\&gt; _timeframeToggles — 每 TF 独立开关
- int _highThreshold — 高阈值（默认 75，范围 0-100）
- int _medThreshold — 中阈值（默认 50，范围 0-100）
- SharedPreferences? _prefs — 延迟初始化

SharedPreferences 键名常量：
- 'alert_tf_toggle_' + tf（如 'alert_tf_toggle_15m'）
- 'alert_high_threshold'
- 'alert_med_threshold'

公开 getter：
- Map\&lt;String, bool\&gt; get timeframeToggles → Map.unmodifiable(_timeframeToggles)
- int get highThreshold → _highThreshold
- int get medThreshold → _medThreshold
- bool getTimeframeToggle(String tf) → _timeframeToggles[tf] ?? false

方法 Future\&lt;void\&gt; load()：从 SharedPreferences.getInstance() 读取 _prefs。初始化 _timeframeToggles 为所有 monitoredTimeframes 的默认值 true（每个 TF 读 SP，无 SP 键则默认 true）。初始化 _highThreshold（默认 75）和 _medThreshold（默认 50）。读取后 notifyListeners()。

方法 Future\&lt;void\&gt; setTimeframeToggle(String tf, bool enabled)：_timeframeToggles[tf] = enabled。_prefs?.setBool('alert_tf_toggle_$tf', enabled)。notifyListeners()。

方法 Future\&lt;void\&gt; setHighThreshold(int value)：_highThreshold = value.clamp(0, 100)。_prefs?.setInt('alert_high_threshold', _highThreshold)。notifyListeners()。

方法 Future\&lt;void\&gt; setMedThreshold(int value)：_medThreshold = value.clamp(0, 100)。_prefs?.setInt('alert_med_threshold', _medThreshold)。notifyListeners()。

注意：阈值范围 0-100 clamp 校验（per RESEARCH.md ASVS V5 Input Validation）。SharedPreferences 为 Android MODE_PRIVATE，非 root 不可外部写入。

不引入 DailyCapTracker（日上限计数器）在此 Provider 中——日上限计数器在 AlertThrottler 内部通过内存维护（per RESEARCH.md Pitfall 2 规避策略：内存 + 跨日重置），无需 SharedPreferences 持久化。若未来需要跨 app 重启保留日计数器，可在 AlertThrottler 中注入 SharedPreferences 引用。
