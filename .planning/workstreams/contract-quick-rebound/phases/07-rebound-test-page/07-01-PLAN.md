    定义 `SimulationMode` 枚举：vRebound / deadCatBounce / randomWalk / steadyDecline。

    定义 `TestDataGenerator` 类：
    - 构造函数接受 `mode`（SimulationMode）、`initialPrice`（默认 100.0）、`seed`（可选 int）
    - 内部状态：`_random`（Random(seed)）、`_lastClose`（初始为 initialPrice）、`_step`（初始为 0）
    - 公开方法 `KlineData nextCandle(DateTime time)`：根据 mode 分派到私有方法
    - 私有方法 `_generateVRebound`：30 根一个周期（phase = _step % 30），0-19 平稳段（close = lastClose + random*1.0 - 0.5），20-22 急跌段（close = lastClose * (0.96 - random*0.01)），23-24 回升段（close = lastClose * (1.04 + random*0.01)，volume 翻倍），25+ 新平稳。每根 high = max(open,close) + random*0.5，low = min(open,close) - random*0.5
    - 私有方法 `_generateDeadCatBounce`：30 根一个周期，0-19 平稳，20-22 急跌（同 vRebound），23-24 弱回补（close = lastClose * (1.01 + random*0.01)，volume 缩半），25-29 继续下跌（close = lastClose * (0.97 - random*0.01)）
    - 私有方法 `_generateRandomWalk`：close = lastClose * (1 + (random - 0.5) * 0.02)，volume = 10 + random*5
    - 私有方法 `_generateSteadyDecline`：close = lastClose * (0.98 - random * 0.01)，volume = 10 + random*5
    - 每个私有方法末尾更新 `_lastClose = close` 并递增 `_step`

    定义 `TestOrchestrator extends ChangeNotifier`：
    - 构造函数接受 `generator`（TestDataGenerator）、`detector`（ReboundDetector）、`params`（ReboundParams，默认 const ReboundParams()）
    - 私有字段：`_timer`（Timer?）、`_window`（List&lt;KlineData&gt;）、`_signals`（List&lt;ReboundSignal&gt;）、`_isRunning`（bool）、`_startTime`（DateTime?）
    - 常量：`windowSize = 50`、`maxSignals = 20`、`interval = Duration(seconds: 5)`
    - 公开 getter：`window`（List.unmodifiable）、`signals`（List.unmodifiable）、`isRunning`
    - `start()` 方法：设置 _isRunning = true，_startTime = DateTime.now()，启动 Timer.periodic(interval, _tick)
    - `pause()` 方法：设置 _isRunning = false，取消 _timer
    - `reset()` 方法：清空 _window 和 _signals，重置 _step 为 0（需要在 TestDataGenerator 上暴露 reset 方法或重新创建 generator），notifyListeners
    - `changeMode(SimulationMode mode)` 方法：暂停，创建新的 TestDataGenerator(mode: mode, seed: 相同 seed)，重置 _window/_signals，notifyListeners
    - `changeParams(ReboundParams params)` 方法：更新 _params，notifyListeners
    - `_tick(Timer timer)` 方法：计算 currentTime = _startTime.add(Duration(seconds: _step * 5))，调用 _generator.nextCandle(currentTime) 追加到 _window，如果 _window.length > windowSize 则 removeAt(0)，调用 _detector.evaluate(_window, _params, symbol: 'TESTUSDT', timeframe: '15m')，如果结果非 null 且 score >= 60 则插入 _signals 头部（超过 maxSignals 则移除末尾），notifyListeners
    - `dispose()` 方法：取消 _timer，调用 super.dispose()

    TestDataGenerator 需要额外暴露 `reset()` 方法重置 _step 和 _lastClose 到初始状态，供 TestOrchestrator.changeMode 和 reset 使用。

    **_buildCandlestickChart()：**
    - 从 _orchestrator.window 获取 K 线数据
    - 如果 window 为空，显示 Center(child: Text('点击开始按钮启动测试', style: TextStyle(color: Colors.grey)))
    - 否则使用 fl_chart 的 CandlestickChart：
      - candlestickSpots: window.asMap().entries.map((e) => CandlestickSpot(x: e.key.toDouble(), open: e.value.open, high: e.value.high, low: e.value.low, close: e.value.close)).toList()
      - candlestickPainter: DefaultCandlestickPainter(candlestickStyleProvider: ...) — 根据最新信号的 dropStartIndex/dropEndIndex/recoveryEndIndex 为对应范围 K 线着色（下跌段红色 Colors.red.shade700、拉回段绿色 Colors.green.shade700、正常灰色根据涨跌方向）
      - 信号索引需要转换：信号的 dropStartIndex/dropEndIndex/recoveryEndIndex 是窗口内的索引，当 window 通过 removeAt(0) 滚动时，信号中的索引会偏移。解决方案：在 TestOrchestrator 的 _tick 中，信号索引基于当前 window 的最后位置记录（即 window.length - 1 为最新），所以信号的 dropStartIndex 等已经是 window 内的绝对索引。但当 window 滚动时旧信号的索引会失效。为此，在绘制时只使用最新一条信号（如果存在）来高亮，且需要将信号索引转换为当前 window 的索引：offset = window.length - (signal.recoveryEndIndex + 1)，然后 dropStartIdx = signal.dropStartIndex - offset 等。如果 offset 导致索引 < 0 则不高亮。

      - titlesData: 左侧显示价格标签，底部不显示（K 线太多标签重叠），右侧不显示，顶部不显示
      - borderData: FlBorderData(show: true, border: Border.all(color: Colors.grey.shade800, width: 0.5))
      - minY: window.map((k) => k.low).reduce(min) * 0.99
      - maxY: window.map((k) => k.high).reduce(max) * 1.01
