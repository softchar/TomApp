创建 `test/services/rebound_detector_test.dart`，使用 `flutter_test` 包。

**辅助函数** `_makeKline()`：快速构造 KlineData 的 helper，接收 close/high/low/open/volume/time 参数，其余给合理默认值。所有测试 fixture 通过此函数构造，避免重复代码。

**测试组结构**（使用 `group('ReboundDetector', () { ... })`）：

**Test 1: V 型反弹 — 完整三阶段通过**
- 构造 ~30 根 K 线：前 20 根平稳（close ~100），第 21-23 根急跌（close 降至 90，跌幅 10 = 约 2×ATR），第 24-25 根快速回补（close 回到 97，回补 70%），成交量拉回段 > 下跌段
- 调用 `evaluate(window, ReboundParams())` → 返回非 null ReboundSignal
- 断言 `signal.score > 70`（强信号）
- 断言 `signal.recoveryRatio > 0.5`
- 断言 `signal.speed <= 2`
- 断言 `signal.deadCatRiskScore < 50`（低死猫风险）

**Test 2: warm-up 数据不足 → null**
- 构造仅 10 根 K 线的 window（少于 ATR warm-up 所需的 14+根）
- 调用 `evaluate(window, params)` → 返回 null
- 断言不抛异常

**Test 3: 死猫反弹 — 弱回补 + 高风险分**
- 构造 ~30 根：急跌后仅回补 35%（<50% 阈值），成交量拉回段 < 下跌段
- 如果 evaluate 返回 null（回补不足 50%），调整 fixture 使回补刚好 52%（刚过阈值）但量能弱
- 断言 `signal.score < 50`（低分）
- 断言 `signal.deadCatRiskScore > 60`（高死猫风险）
- 断言 `signal.confluenceFilters` 不含 `ConfluenceType.volumeConfirmation`

**Test 4: 下跌中继 — 回补不足 → null**
- 构造 ~30 根：急跌后仅回补 30%（<50% 阈值）
- 调用 `evaluate(window, params)` → 返回 null
- 断言：回补不足时不应产生信号

**Test 5: lookahead 抵御 — 信号仅在收盘后触发**
- 构造完整 V 型反弹 fixture，但最后一根 K 线标记为「未收盘」（通过构造方式：最后一根的 close 设为中间值，模拟 partial candle）
- 实际测试方式：构造 window 使最后一根 K 线的 close 不满足回补条件，但若用了未来数据会满足
- 断言 evaluate 返回 null（说明没用未来数据）

**Test 6: 纯函数幂等 — 同一输入两次调用结果一致**
- 构造一个标准 V 型反弹 fixture
- 调用 `evaluate(window, params)` 两次
- 断言两次结果的 `score`、`deadCatRiskScore`、`recoveryRatio`、`dropMagnitude` 完全相等
- 断言两次结果的 `confluenceFilters` 集合相等

**Test 7: RSI 超卖拐头触发共振过滤**
- 构造 fixture 使 RSI(14) 从 <30 拐头向上（需要足够多根 K 线先建立 RSI 序列）
- 调用 evaluate → 检查 `signal.confluenceFilters` 包含 `ConfluenceType.rsiOversoldTurning`
- 如果 RSI 数据不足以触发，可改用验证 `_checkConfluence` 的行为（通过 evaluate 间接测试）

**Test 8: 放量确认触发 volume 共振**
- 构造 fixture：拉回段成交量是下跌段的 2 倍
- 断言 `signal.confluenceFilters` 包含 `ConfluenceType.volumeConfirmation`

**Test 9: 评分范围验证 — 输出在 [0, 100]**
- 构造多个不同场景的 fixture（强反弹、弱反弹、边界情况）
- 对每个 fixture 断言 `signal.score >= 0 && signal.score <= 100`
- 断言 `signal.deadCatRiskScore >= 0 && signal.deadCatRiskScore <= 100`

**Test 10: ReboundConfluenceScorer 单 TF 返回 0**
- 构造 `Map<String, ReboundSignal?>` 只含一个 TF
- 调用 `ReboundConfluenceScorer.scoreMultiTimeframe(map)` → 返回 0

**Test 11: ReboundConfluenceScorer 多 TF 加分**
- 构造 map 含 3 个 TF 的信号
- 调用 scoreMultiTimeframe → 返回 10（(3-1) × 5 = 10）

**通用 fixture 构造模式**：
- 使用 `_makeKline()` helper，传入 DateTime 递增（每根间隔 15 分钟模拟 15m 周期）
- ATR 需要 ≥ 14 根数据才有有效值，所以 fixture 至少 25-30 根
- 跌幅段 K 线：high 不变，low 和 close 大幅下降
- 回补段 K 线：close 快速回升，volume 放大
- 通过调整 close 值精确控制回补比例（如 50%、70%、30%）
